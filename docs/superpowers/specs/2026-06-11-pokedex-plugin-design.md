# Pokédex KOReader Plugin — Design Spec

Date: 2026-06-11

## Goal

While reading a Pokémon fanfic on Kindle, long-press a Pokémon's Chinese name to see a popup showing the Pokémon's official artwork and English flavor text — like a dictionary lookup, but visual.

---

## Data Source

**Repository**: `Purukitto/pokemon-data.json`

Single `git clone` (or zip download). No API requests at runtime.

Relevant files:
- `pokedex.json` — 898 Pokémon (Gen 1–8), one entry per Pokémon
- `images/pokedex/hires/{id}.png` — 400×400 RGBA official artwork

Key fields used per entry:
```json
{
  "id": 114,
  "name": { "english": "Tangela", "chinese": "蔓藤怪" },
  "type": ["Grass"],
  "species": "Vine Pokémon",
  "description": "Tangela's vines snap off easily...",
  "image": { "hires": "...images/pokedex/hires/114.png" }
}
```

Gen 9 Pokémon (899+) are not covered. Acceptable for this use case.

---

## Plugin Architecture

### Directory layout

```
pokedex.koplugin/
├── _meta.lua
├── main.lua
└── data/
    ├── pokedex.lua        ← compiled lookup table (generated from pokedex.json)
    └── hires/
        ├── 1.png
        ├── 4.png
        └── ...            ← only Pokémon that appear in the fanfic, or all 898
```

`pokedex.lua` is generated once by a Python script. It exports a Lua table mapping every known name variant to an entry:

```lua
return {
  ["蔓藤怪"] = { id=114, en="Tangela", type="Grass", species="Vine Pokémon",
                 desc="Tangela's vines snap off easily..." },
  ["tangela"]  = { ... },  -- lowercase English name
  ...
}
```

Index keys: simplified Chinese name + lowercase English name. Both point to the same entry table.

### Data generation script (`make_pokedex_data.py`)

Reads `pokedex.json`, writes `data/pokedex.lua` and copies image files into `data/hires/`. Run once locally, output committed alongside the plugin.

---

## Trigger & Lookup Flow

1. Plugin registers a listener on `onWordSelection` (the same event that triggers dictionary lookup).
2. On selection, normalize the word: strip whitespace, lowercase.
3. Look up normalized word in the Lua table.
4. **Match**: intercept the event, show Pokédex popup. Normal dictionary flow does not run.
5. **No match**: do nothing. Normal dictionary flow runs as usual.

This means the Pokédex popup replaces the dictionary popup for Pokémon names, and leaves everything else untouched.

---

## Popup Layout

E-ink black-and-white, no color:

```
┌─────────────────────────────┐
│  [image 100×100]  #114 蔓藤怪│
│                   Tangela   │
│                   Grass     │
│                   Vine Pokémon
├─────────────────────────────┤
│ Tangela's vines snap off    │
│ easily if they are grabbed. │
│ ...                         │
│                    [close]  │
└─────────────────────────────┘
```

- Image rendered via KOReader's `ImageWidget`, grayscale on e-ink naturally
- Text via `TextBoxWidget`
- Whole popup wrapped in a `FrameContainer` shown with `UIManager:show()`
- Close on tap anywhere outside, or a close button

---

## Non-goals

- No ability stats, EV yields, or move lists
- No evolution chain display
- No online lookup at read time
- No Gen 9 coverage
- No per-version flavor text switching (one description per Pokémon)

|------|--------|
| `pokedex.koplugin/_meta.lua` | Create |
| `pokedex.koplugin/main.lua` | Create |

| `pokedex.koplugin/data/pokedex.lua` | Generated by script |
| `pokedex.koplugin/data/hires/*.png` | Copied by script |

`make_pokedex_dict.py` (the old StarDict approach) can be deleted.
